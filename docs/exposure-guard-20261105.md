# 分批加仓与资金护栏同步记录

本次将已经部署的加密货币监控 Python 源码同步到现有维护分支。GitHub push 本身不会部署或重启服务，不包含凭据、运行配置、日志或数据库。独立股票观察器不属于此次同步范围。

## 行为

允许有持仓时继续给出 BUY。AI 原始 BUY 比例仍表示可用现金的10%-50%；执行器只能下调最终金额，不能放大原始意图。新增 BUY 受单币60%与可用现金20%两项限制；既有持仓涨价超限不会强制卖出。

全局现货净值包括可用/冻结USDT、全部现货币种与灰尘。缺失直接 ASSET/USDT 盘口、行情超过60秒、盘口异常或估值阶段超过15秒时拒绝新增BUY。无法直接估值的资产不按零处理；未实现多跳换算。2%盘口价差限制是数据/流动性过滤参数，不是收益判断。

手续费预算率为账户taker费率与0.5%的较大值，读取失败采用0.5%预算；实际收费由交易所决定。元数据、手续费、价格变化与外部手动交易仍可能改变执行结果，不能保证比例永久不超限。

锁覆盖本系统账户执行路径。存在挂单时先不新增BUY；发生提交超时或未终态部分成交时保留待核实状态，不能自动重发。正常委员会的已核实终态可以按client_oid和订单身份同步到执行状态库。绕过委员会的未知订单需要单独核实，不得删库恢复。

本机使用与线上一致的CCXT4.5.59执行8套隔离测试，全部通过；其中46项新增测试覆盖资金、估值、精度、幂等、并发和已核实状态恢复。真实CCXT请求构造器测试确认市价买单的原生amount使用USDT报价金额。临时HOME、虚构配置与网络禁用由tools/run_tests.py强制注入。

生产Python源码已读取并与本地交付清单核对；实际服务目录指向新release、active且重启计数为0。未人为触发实盘订单、模型请求或微信消息；巡检运行不代表新的BUY路径已获得自然成交验证。

原FIFO多批测试第二次买入从20%改为10%，保持其低于新集中度上限，仍验证FIFO净盈亏和现金余额；提示词哈希更新为本次已授权版本。其余六个角色提示词由新增独立哈希断言保持。

## 继承的核实边界

11月3日已经存在的 `GateReadOnly.order_by_text` 每种状态最多查询100条；`OrderJournal.reconcile` 含有“按client_oid未找到且超过60秒就标cancelled”的分支。有限列表未找到不能证明未提交，该分支不是可靠的无订单证明。本次按线上源码原样同步，没有擅自改生产逻辑。

当前 `ExecutionGuard.blocked` 只主动核实带order_id的记录；因此不能声称无订单号的未知记录会自动恢复。新增执行层也不会仅因上述无成交备注而解锁：需要匹配订单号与已核实终态evidence。仍应单独修复该继承分支，而不是把测试全绿当作它正确的证明。

状态库不在Git中。后续版本切换/回滚都应保留并核对两个订单状态库，不能通过删除任一数据库解除交易拦截。
